# 코딩테스트 연습 - 달리기 경주 (LV.1)

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/178871)

## 풀이

**1. 이름이 불리면 바로 앞 선수와 자리를 바꾼다.**

한 번 불릴 때마다 한 명만 추월하므로, 두 선수의 위치만 교환하면 된다.

<span style="color:red">ex)</span>

```text
호출 전: mumu, soe, poe, kai, mine
kai 호출
호출 후: mumu, soe, kai, poe, mine
```

문제는 이 교환을 빠르게 처리하는 것이다.

<br>

**2. 선수의 현재 위치를 딕셔너리에 저장한다.**

```python
position = {name: i for i, name in enumerate(players)}
```

- `players[i]` → i번 위치의 선수 이름
- `position[name]` → 해당 선수의 현재 위치

<span style="color:red">ex)</span>

```python
{
    'mumu': 0,
    'soe': 1,
    'poe': 2,
    'kai': 3,
    'mine': 4
}
```

등수는 1부터지만 배열 인덱스는 0부터이므로, 여기에는 **등수보다 1 작은 인덱스**를 저장한다.

매번 `players.index(name)`으로 찾으면 최대 50,000명의 선수를 반복해서 확인해야 한다.

딕셔너리로 위치를 관리하면 호출된 선수의 위치를 평균 O(1)에 찾을 수 있다.

<br>

**3. 호출된 선수와 바로 앞 선수의 이름을 구한다.**

```python
idx = position[name]
front = players[idx - 1]
```

현재 위치가 `idx`라면 바로 앞 선수는 `idx - 1`에 있다.

경주 중 1등 선수는 호출되지 않는다는 조건이 있으므로 `idx`는 항상 1 이상이다.

<br>

**4. 배열과 딕셔너리를 모두 갱신한다.**

```python
players[idx - 1], players[idx] = players[idx], players[idx - 1]
position[name] = idx - 1
position[front] = idx
```

- 호출된 선수 → 한 칸 앞으로 이동
- 추월당한 선수 → 한 칸 뒤로 이동

배열의 순서뿐 아니라 두 선수의 위치 정보도 함께 바꿔야 다음 호출을 정확히 처리할 수 있다.

매 호출 후에도 `players[position[name]] == name`이 유지되도록 관리하는 것이다.

<br>

**5. 모든 호출을 처리한 배열이 최종 순위다.**

<span style="color:red">ex)</span> `callings = ['kai', 'kai', 'mine', 'mine']`

```text
시작       mumu, soe, poe, kai, mine
kai 호출   mumu, soe, kai, poe, mine
kai 호출   mumu, kai, soe, poe, mine
mine 호출  mumu, kai, soe, mine, poe
mine 호출  mumu, kai, mine, soe, poe
```

따라서 최종 배열을 그대로 반환하면 된다.

```python
return players
```

이 풀이는 전달받은 `players` 리스트에서 직접 순서를 바꾼다.

## 오답노트

아래는 구현할 때 주의할 점이다.

**1. 매번 `index()`로 찾으면 시간 초과가 날 수 있다.**

```python
for name in callings:
    idx = players.index(name)
```

선수 수를 N, 호출 수를 M이라고 하면 최악의 경우 O(N × M)이다.

최대 입력에서는 50,000 × 1,000,000으로 약 500억 번의 탐색 비교가 필요할 수 있다.

선수 위치를 딕셔너리에 저장해서 반복 탐색을 없애야 한다.

<br>

**2. 호출된 선수의 위치만 바꾸면 안 된다.**

```python
position[name] = idx - 1
position[front] = idx
```

앞 선수도 뒤로 밀렸으므로 두 선수 모두 갱신해야 한다.

한 명만 갱신하면 같은 위치에 두 선수가 있다고 기록되는 등 정보가 어긋난다.

<br>

**3. 앞 선수의 이름은 교환 전에 저장한다.**

```python
front = players[idx - 1]
```

교환한 뒤 `players[idx - 1]`을 확인하면 그 자리에는 이미 호출된 선수가 있다.

추월당한 선수의 위치를 갱신하려면 먼저 이름을 기억해 두어야 한다.

<br>

**4. 호출 횟수만 세어 한 번에 등수를 빼면 안 된다.**

어떤 선수가 추월하면 다른 선수는 한 칸 밀려난다.

각 호출 시점의 바로 앞 선수가 달라질 수 있으므로, **호출 순서대로** 실제 자리를 바꿔야 한다.

<br>

**5. 정렬로 최종 순위를 다시 만들 필요가 없다.**

`players`는 처음부터 순위 순서이며, 호출마다 실제 위치를 교환하고 있다.

모든 호출을 처리한 순간 이미 최종 순위 배열이 완성된다.

---

## 정답

```python
def solution(players, callings):
    position = {name: i for i, name in enumerate(players)}

    for name in callings:
        idx = position[name]
        front = players[idx - 1]

        players[idx - 1], players[idx] = players[idx], players[idx - 1]
        position[name] = idx - 1
        position[front] = idx

    return players
```

### 한 줄씩

- `enumerate(players)` → 초기 위치와 선수 이름을 함께 가져오기
- `position = {...}` → 선수 이름으로 현재 위치를 찾는 딕셔너리
- `for name in callings:` → 호출 순서대로 추월 처리
- `idx = position[name]` → 호출된 선수의 현재 위치
- `front = players[idx - 1]` → 추월당할 앞 선수의 이름 저장
- `players[idx - 1], players[idx] = ...` → 두 선수의 자리 교환
- `position[name] = idx - 1` → 추월한 선수의 위치 갱신
- `position[front] = idx` → 추월당한 선수의 위치 갱신
- `return players` → 1등부터 나열된 최종 순위 반환

### 시간 복잡도

선수 수를 `N`, 호출 수를 `M`이라고 하면 초기 딕셔너리를 만드는 데 O(N)이 걸린다.

이름 길이가 최대 10인 제한사항에서 딕셔너리 조회와 갱신은 평균 O(1)이므로, 전체 호출 처리는 평균 O(M)이다.

따라서 **전체 시간 복잡도는 평균 O(N + M)**이고, 위치 딕셔너리를 저장하므로 **추가 공간 복잡도는 O(N)**이다.

### 한 줄 요약

> 선수별 현재 위치를 딕셔너리로 관리하고, 호출마다 바로 앞 선수와 배열의 자리를 바꾼 뒤 두 선수의 위치를 함께 갱신한다.
